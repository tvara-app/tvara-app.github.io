Claude usage limits: the five-hour session and the weekly cap

Short answer: Claude meters use in a five-hour session and a weekly limit, and the usage page in Claude's settings shows how much of each is gone and when it resets. Long conversations and large files use it fastest, because Claude reads the whole chat again with every message.

The message arrives mid-task: you have reached your limit, come back later. Two limits sit behind it, and knowing which one stopped you tells you whether to wait a few hours or plan around the rest of the week.

The two limits

  • The session limit. A five-hour window. When it runs out, Claude stops answering until the window resets, and tells you when that will be.
  • The weekly limit. A cap on total use across the week, on top of the sessions. You can have session allowance left and still be stopped by the week.

Neither is a fixed number of messages. Usage is weighted: a short question in a new chat costs little, and a long answer late in a long chat with files attached costs a lot. That is why the same plan can feel generous one day and tight the next.

Where to see what is left

Claude's settings have a usage page that shows both limits: how much of the current session and of the week you have used, and when each resets. It is accurate. It is also a page you have to go and open, which is why most people find out from the error message instead.

Why long chats use it up faster

Claude does not remember a conversation between messages. Every time you send one, the whole conversation goes back to the model and is read again. Message two hundred of a long chat carries the other hundred and ninety-nine with it. More on how the context window works.

How to make it last

  1. Start a new chat when the topic changes. A fresh chat is cheap per message; a long one is expensive. Carry the decisions across, not the transcript. A handover that works.
  2. Keep reference files in a project. Add a document to a project once instead of pasting it into chat after chat.
  3. Ask for the change, not the whole thing. Asking for only the changed lines of a long file costs far less than a full rewrite every time.
  4. Save heavy features for heavy work. Research and long tool runs use more of the allowance than a plain question.
  5. Front-load the expensive work. Large files and long analysis early in a session; quick questions near the end of it.
